# 云计算手册

量潮工作手册研发目录下的云计算子手册，讲的是怎么把云函数、存储、数据库、工作流、权限和发布流程组织成可部署、可观测、可回退的云端系统。云计算管理的重点不是把服务开起来，而是把资源边界、环境隔离、凭据治理和运维证据说清楚。

## 云端场景

- 函数计算、Serverless Framework、云函数和轻量后端服务。
- 需要把云资源、配置、凭据、发布和运维统一管理的项目。
- 同时使用对象存储、文件存储、数据库、缓存和消息队列的状态型系统。
- 把会议、协作、数据处理、AI 调用等 SaaS 能力接入云端工作流的场景。

## 云资源治理原则

- 先定业务场景和运行形态，再选云服务。
- 先定资源边界、权限边界和成本边界，再写业务代码。
- 代码、配置、凭据、资源名称和文档要同步治理。
- 开发环境、测试环境、生产环境必须明确区分。
- 云资源变更要能追溯，发布结果要能验证和回退。
- 有状态资源要单独记录备份、迁移、清理和保留周期。

## 云能力地图

| 章节 | 内容 |
|------|------|
| 项目框架 | 函数计算项目的目录、入口、配置和文档约定 |
| DevOps流程 | Serverless Framework、CI、凭据、环境变量和发布证据 |
| 有状态资源 | 缓存、数据库、对象存储、文件存储和保留周期 |
| 工作流编排 | 多步骤任务、爬虫、自动化测试、数据分析和失败重试 |
| 层管理 | 公共依赖、共享运行时、复用策略和兼容性 |
| Web框架 | Django 等 Web 框架在云函数中的适配和部署 |
| SaaS集成 | 会议、协作、数据处理等外部能力的接入规范 |

新增云端项目时，先写一份资源清单：

- 运行入口是什么。
- 用到了哪些云资源。
- 哪些资源有状态。
- 凭据和环境变量在哪里配置。
- 发布后怎么验证访问、日志和回退。

## 云项目交付标准

- 有清晰的项目结构、运行入口和触发方式。
- 有可复现的环境变量、凭据、资源配置和权限说明。
- 有构建、部署、调试、验收和回退步骤。
- 有云资源命名、环境隔离、访问权限和成本标识。
- 有日志、监控、告警、故障处理和资源清理记录。

## 部署前检查

- 资源名称是否带项目和环境标识
- 环境变量是否未提交到 Git
- 凭据是否走受控的 CI 或密钥管理
- 云函数入口和依赖是否明确
- 数据库、存储和网络是否完成隔离
- 部署后是否能验证访问和回退
