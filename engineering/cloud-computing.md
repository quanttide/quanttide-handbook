# 云计算手册

量潮工作手册研发目录下的云计算子手册，记录函数计算、云存储、工作流编排、Web 框架和 SaaS 集成场景中的工程规范。当前素材主要来自 Python 项目和腾讯云云函数实践；后续再扩展到其他语言、云厂商和运行平台。

## 适用范围

- 函数计算、腾讯云云函数、Serverless Framework 和轻量后端服务。
- 需要通过`serverless.yml`描述云函数、环境变量、网络、存储和部署配置的项目。
- 需要把腾讯云凭据、CI 构建计划、`.env`文件和发布验收串起来的项目。
- 需要对象存储、文件存储、数据库、缓存等状态资源协同工作的场景。
- 需要把腾讯会议等 SaaS 能力接入云函数、回调或工作流的场景。

## 工作原则

- 先定业务场景，再选云服务。
- 当前函数计算实践默认以 Python 和腾讯云云函数为主要样本。
- 代码、配置、凭据和文档要同步治理。
- 开发环境、测试环境和生产环境要明确区分。
- 云资源变更要能追溯，发布结果要能回退。
- 环境变量和密钥文件不得进入 Git；误提交应视为工程事故并及时处理历史记录。

## 项目结构

函数计算项目要把代码、配置、文档和环境变量分开。

基本对象：

- 根目录保留`serverless.yml`。
- 云函数可以是单个，也可以是多个；即使只有一个函数，也按多函数项目处理，便于后续扩展。
- 每个云函数目录可以包含 0-N 个 Python 模块或包。
- 文档目录记录云函数入口、环境变量、资源依赖和部署验收方式。

`serverless.yml`里常用两类变量：

- `${app}`：项目名称，通常加在云资源名称开头，用于区分项目资源。
- `${stage}`：环境标识，通常加在云资源名称末尾，用于区分开发、测试和生产资源。

环境变量按 Serverless Framework 的格式读取：

```text
${env:<ENV_VARIABLE>}
```

本地`.env`文件要加入`.gitignore`。CI 部署时再临时生成`.env`，不能把数据库密码、API 密钥等敏感变量写进仓库。

## CI 和凭据

函数计算项目的 CI 重点是把环境变量、凭据、部署和验收串成一条线。

构建计划通常使用团队模板：

```text
函数计算项目-**环境
```

不同环境后缀主要区别在于：

- `STAGE=dev`：开发环境。
- `STAGE=testing`：预生产或测试环境。
- `STAGE=master`：生产环境。

默认数据库、COS、私有网络等配套云资源也要随环境区分。

腾讯云 API 密钥在 CI 的凭据管理中维护：

1. 在项目设置的凭据管理中创建从腾讯云控制台获取的 API 密钥。
2. 在变量与缓存中配置非敏感环境变量。
3. 在部署阶段的`withCredentials`部分，把云函数需要的环境变量写入临时`.env`文件。
4. 在云函数的`serverless.yml`环境变量部分读取这些变量。

写入`.env`时保持 CI 变量名和云函数变量名一致，减少混淆：

```bash
echo <ENV_NAME_IN_SERVERLESS>=${ENV_NAME_IN_CI}\n > .env
```

## Serverless Framework

Serverless Framework 部署函数计算项目时，至少检查：

- `serverless.yml`能否读取所需环境变量。
- 腾讯云子账号授权是否完成。
- DB、私有网络、COS 和云函数是否按环境分开。
- 本地配置和 CI 配置是否一致。
- 发布后是否能查看云函数版本、日志和访问结果。

权限配置要按腾讯云子账号授权流程处理，尤其注意最小权限和部署所需资源范围。

## 存储和有状态资源

函数计算本身强调无状态，但真实业务通常需要把状态交给受控云资源。

常见资源：

| 资源 | 当前实践关注点 |
|------|----------------|
| DB | 基于实例和数据库隔离；不同项目优先用数据库隔离 |
| 私有网络 | 跟随 DB 和云函数配置，避免不同项目资源混用 |
| COS | 同地域优先，减少内网流量和跨地域成本 |
| CFS | 用于需要挂载目录的计算任务 |

CFS 挂载约定：

- 本地目录是云函数本地文件系统的挂载点。
- 使用`/mnt/`目录下的子目录挂载 CFS 文件系统。
- CFS 文件不能像普通本地文件一样直接观察时，通过函数运行结果间接验证。

CFS 调试步骤：

1. 通过 CI 部署到云端。
2. 手动运行下载文件到 CFS 的函数，检查运行结果。
3. 手动运行分析 CFS 文件的函数，检查运行结果。

## 工作流编排

工作流适用于流程固定、大批量重复、部分步骤可以复用的场景，比如网页爬虫、数据分析、自动化测试。

爬虫类工作流可以拆成四类云函数：

1. 调度：决定何时运行、运行哪些目标。
2. 请求：访问页面或接口并保存原始响应。
3. 解析：把原始响应解析为结构化数据。
4. 存储：把 SQL-like 或 NoSQL-like 数据写入指定存储。

可选存储包括：

- CynosDB / MySQL。
- 云开发云数据库 / MongoDB。
- 对象存储 / 云开发云存储。

对于每一类数据，尽量提供贴合固定场景的二次封装 API。这样比直接暴露云存储复杂接口更易用，也更符合云原生“基于 API 的协作”原则。

云函数本身的事件函数机制可以承担异步调度管理，避免开发者在 Python 内部实现过于复杂的异步逻辑。

## Web 框架

Django 等 Web 框架可以部署到云函数、容器或其他云端运行环境，适用于管理后台、API 服务或轻量 Web 应用。

接入时要检查：

- Web 入口是否适配云函数运行方式。
- 数据库、缓存、存储桶和密钥是否通过环境变量注入。
- 静态文件和媒体文件是否有云端存储方案。
- 数据库迁移步骤是否明确。
- 部署后是否能验证访问、日志和错误响应。

## 腾讯会议接入

腾讯会议属于会议类 SaaS 接入场景，适用于会议创建、会议查询、事件回调、录制处理和会议数据同步。

接入前确认：

- 腾讯会议账号、企业主体和应用权限。
- API 调用身份和密钥保存方式。
- 回调地址、验签方式和重试策略。
- 会议数据的存储位置和保留周期。

运行要求：

- 凭据不进入 Git。
- 回调接口记录请求和处理结果。
- 回调事件要能验签、去重和重放。
- 会议数据按业务场景分级保存。
- 失败任务要能重试，重复事件要能去重。

## 部署前检查

- 根目录是否有`serverless.yml`
- 云函数目录、入口文件和 Python 依赖是否明确
- `STAGE`和环境变量是否按环境区分
- `.env`是否已加入`.gitignore`
- 腾讯云凭据是否在 CI 凭据管理中维护
- DB、私有网络、COS、CFS 和云函数是否按项目和环境隔离
- CFS 挂载路径是否使用`/mnt/`子目录
- 腾讯会议回调是否启用验签、重试和去重
- 部署后是否能验证访问、日志、云函数版本和回退方式
