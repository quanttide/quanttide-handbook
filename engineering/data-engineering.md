# 数据工程手册

量潮工作手册研发目录下的数据工程子手册，记录数据采集、预处理、建模、可视化、治理、DataOps 和数据交付的实践。数据工程不是把文件处理完就结束，而是要说明数据从哪里来、如何被处理、以什么格式交付、质量如何验证、后续怎么复盘。

## 数据项目边界

- 从网站、数据库、文本文件、社交媒体、移动应用程序、传感器或业务系统采集数据。
- 对原始数据做清洗、转换、标注、建模、分析和可视化。
- 把数据集或数据应用交付给利益相关方。
- 需要托管执行、按次记录、计量成本和复盘质量的数据任务。
- 需要 AI 参与字段解释、爬虫代码生成、数据标注、格式转换、报告生成和异常提示的场景。

## 工作原则

- 先明确交付目标，再梳理数据处理主线。
- 先定义数据边界、字段口径和使用限制，再写处理流程。
- 每个输入、处理步骤、人工修正和输出都要能追溯。
- 自动化优先，人工判断必须留下依据和责任人。
- 数据质量问题要显式记录，不能被漂亮的结果页掩盖。
- 一次交付要同时交结果、口径说明、运行证据和复盘信息。

## 数据工程流程

数据工程流程框架分为三步：

1. 明确交付目标：确认交付给哪些利益相关方、交付什么数据、以什么形式和渠道交付。
2. 梳理主线流程：梳理数据采集、预处理、建模到可视化的关键步骤。
3. 制定研发流程：定义责任分配、工作流程和问题调整策略。

在总手册里落地时，可以拆成以下生命周期。

## 定义数据问题

定义阶段先把边界定清楚。没有明确业务问题的数据处理，最后很容易只交出一堆无法判断价值的表。

- 明确业务问题和目标受众。
- 明确输入数据源。
- 明确输出格式。
- 明确验收标准。
- 明确权限、保密要求和交付渠道。

输出物：

- 数据工程蓝图。
- 输入清单。
- 输出清单。
- 验收口径。
- 风险和限制说明。

## 采集数据源

数据采集是从各种来源获取数据的过程，来源可以包括物理资源和数字资源，例如传感器输入、文本文件、数据库、网站、社交媒体、移动应用程序等。

采集阶段至少记录：

- 采集目标。
- 数据来源。
- 数据格式。
- 采集方式。
- 采集时间。
- 采集人或采集程序。
- 权限和登录方式。

### 爬虫采集

爬虫类任务要区分简单页面、复杂页面、高并发采集和反爬场景。

复杂页面处理时，优先分析调用栈和相关源码；可使用 AI 辅助分析网页前端源码。未混淆代码可以直接分析，混淆代码要单独评估难度。

云端部署和本地运行的主要差异在登录态：

1. 增加爬虫 cookies 的文件传输方式。
2. 将程序传输到服务器。
3. 在服务器命令行配置依赖。
4. 读取 cookies 文件。
5. 按正常流程运行。

高并发爬取可以用数据库状态字段控制：

- 未爬取、爬取中、已爬取分别使用不同数字值，例如`1`、`-1`、`0`。
- 失败次数可以用数字累加记录。
- 爬取端只筛选未爬取目标，或失败次数未达上限的目标。
- Redis 等响应快的数据库可以及时反映当前爬取状态。

反爬和运行平台选择要明确：

- 函数 FaaS / Lambda：适合批量启动，函数实例可能在回收前复用。
- 容器：适合依赖较重、部署形态稳定的任务。
- 虚拟机：适合需要独立环境、长时间运行或复杂调试的任务。

日志要多输出关键步骤。日志可以输出到对象存储、日志服务或文件；函数计算可直接打印并由平台记录。人工定期检查或平台自动读取日志后提醒使用者。

## 清洗和预处理

预处理把数据整理成模型、分析或交付需要的格式。

常见动作：

- 去除冗余数据。
- 处理缺失值、异常值和重复记录。
- 统一字段名、类型、单位和编码。
- 转换数据格式和结构。
- 添加标签、元数据和关联信息。
- 保留自动清洗规则和人工修正记录。

处理质量会影响后续分析和应用，因此清洗规则不能只写在代码里，也要进入交付说明或处理报告。

## 数据转换

建议把数据先转为 JSON 作为中转格式，再根据客户定义的目标结构化数据格式转换。

转换流程：

1. 定义目标结构化数据格式，并和需求方核对。
2. 将数据统一整理为 JSON 中转格式。
3. 根据客户需求，将 JSON 转为其他格式。
4. 用代码完成格式转换并交付。

默认约定：

- 本地中转使用 JSON 文件。
- 云端数据库可以用 JSON 字段。
- 为了易读，`json.dumps`或`json.dump`使用`indent=2`。
- 最终格式转换代码可以由大模型辅助编写，但必须人工检查字段、类型和示例数据。

## 数据标注

数据标注是给原始数据添加标签或注释，使机器学习模型能够理解数据中的模式和特征。

常见类型：

- 分类标注：把数据划分到不同类别，例如新闻分类、邮件分类。
- 框定标注：在图像或视频帧中圈出目标物体，适用于目标检测。
- 语义分割标注：把图像中的像素分配到类别，适用于医学影像、遥感图像等。
- 序列标注：适用于文本、音频等序列数据，例如命名实体识别。

文本标注流程：

1. 确定分类任务和标签体系。
2. 准备代表性文本数据。
3. 由标注人员按标签体系标注。
4. 评估标注一致性和准确性。
5. 生成文本-标签对数据集，用于模型训练和测试。

### 文本分类和文本标签

数据标注中要区分 label 和 tag：

| 对象 | 含义 | 示例 |
|------|------|------|
| Label | 通常来自固定类别集合，用于监督学习任务 | “正面评价”“垃圾邮件”“环境” |
| Tag | 更灵活，可以是多个，用于内容组织、搜索或标签云 | “AI”“Python”“深度学习” |

文本分类示例：

- 文本：“产品质量很差，不推荐购买。”
- 标签：“负面”

文本标签示例：

- 文本：“Python是一个流行的编程语言。”
- 标签：`Python`、`技术`、`编程`

### AI 标注

大模型参与标注时，有三类常见方法：

1. 直接提示标注法：用清晰提示词让模型直接分类或抽取。
2. 少样本学习标注法：先人工标注少量代表性样本，再让模型标注剩余数据。
3. 微调模型标注法：准备一定规模标注数据，微调基础模型后再批量标注。

长文本标注时，文本越短，AI 回答通常越稳定。可先把长文本按内容切成文本块，再让模型定位相关文本块并提取目标答案。

RAG 也可以用于字段相关文本提取，但要注意效果不佳的风险：某些字段对应文本很难通过向量相似度比较出来，例如“户籍”相关句子可能只是一段身份描述。

## 数据治理

治理阶段把数据变成可复用资产。字段口径、权限、保留周期和版本变化要一起维护。

- 建立数据字典。
- 建立字段口径。
- 建立质量规则。
- 建立权限和保留周期。
- 建立版本和追溯记录。
- 记录数据来源、处理代码、处理参数和运行结果。

DataOps 关注把敏捷开发、精益管理和统计过程控制应用到数据分析中，使数据集成更快、数据质量管理更准确、数据治理更有效。

## 数据交付

数据交付是将处理后的数据交付物提交给利益相关方的过程。数据交付物分为两类：

- 数据集：在特定领域或任务中收集、组织和存储的一组相关数据。
- 数据应用：基于数据能力形成的应用程序、接口、分析工具或可视化系统。

数据集交付格式要先定义：

1. 确定数据格式，例如 JSON、CSV 等。
2. 精确到表、字段和示例数据。
3. 明确交付渠道、权限和使用限制。
4. 明确是否需要格式转换代码。

交付流程：

1. 在定义交付格式之后开始交付。
2. 默认使用 JSON 半结构化数据做中转。
3. 针对客户需求，将 JSON 转成其他格式。
4. 用代码按客户需求转换数据格式并交付。
5. 同步交付口径说明、质量检查和已知风险。

## 托管执行

托管执行把一次数据工程统一成一次 run。

```text
单价 = 执行时长 × 资源档位系数 × 是否可抢占
```

AI、统计计算、报告生成、模板实例化都可以作为一次 run 里的 resource。对外只需要讲一次执行的价格，对内再记录计算、存储、AI 调用和人工处理成本。

审计记录至少包括：

- run id。
- job 状态。
- 开始和结束时间。
- 输入和输出校验结果。
- 成本和资源记录。
- 人工修正记录。

## 数据交付标准

- 有明确的任务边界。
- 有可访问的数据源记录。
- 有可复现的处理流程。
- 有数据采集和登录态处理说明。
- 有质量检查结果。
- 有 JSON/CSV 等交付格式说明，并精确到表、字段和示例数据。
- 有报告、证据链、成本和耗时记录。
- 有后续维护建议。

## 数据质量检查

- 输入来源、采集时间和权限是否清楚
- cookies、登录态或外部接口凭据是否按规则处理
- 字段口径、单位、枚举值和缺失值是否明确
- 清洗规则、人工修正和异常样本是否留痕
- 标注任务是否区分 label 和 tag
- 流水线、参数、依赖和运行环境是否可复现
- 结果是否通过质量检查和业务验收
- 交付格式是否精确到表、字段和示例数据
- 证据链是否覆盖输入、处理、输出和成本
- 复盘记录是否补齐，并能指导下一次任务
