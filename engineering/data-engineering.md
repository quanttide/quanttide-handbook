# 数据工程手册

量潮工作手册研发目录下的数据工程子手册，讲的是怎么把数据采集、清洗、治理、计算、交付和复盘连成一条可执行、可审计、可复用的数据工程链路。

## 适用范围

- 适用于需要把原始数据加工成交付结果的数据项目。
- 适用于需要托管执行、按次记录和复盘成本的数据任务。
- 适用于多个数据源、多个处理阶段和多个交付对象共存的场景。
- 适用于需要 AI 参与需求澄清、流程设计、结果解释和报告生成的场景。

## 工作原则

- 先定义数据边界，再定义处理流程。
- 每个输入、处理步骤和输出都要能追溯。
- 自动化优先，人工判断要留下依据。
- 数据质量问题要显式记录，不能被结果页掩盖。
- 一次交付要同时交结果、说明、证据和复盘信息。

## 角色分工

- 负责人负责确认目标、范围、验收口径和风险边界。
- 数据工程负责设计数据流、处理逻辑、质量规则和异常处理。
- 平台负责提供运行环境、权限、计量、日志和审计能力。
- AI 负责补齐蓝图、整理步骤、生成报告草稿和提示异常。
- 审计负责核对事实源、成本口径、结果证据和复盘记录。

## 关键对象

| 对象 | 含义 |
|------|------|
| `source` | 数据来源 |
| `dataset` | 数据集 |
| `pipeline` | 数据处理流水线 |
| `blueprint` | 一次数据工程任务的定义 |
| `run` | 一次可记录、可计量的执行 |
| `job` | run 的运行状态记录 |
| `report` | 对外交付的报告或结果说明 |
| `audit log` | 审计证据和追踪记录 |

## 生命周期

### 定义

定义阶段先把边界定清楚。

- 明确业务问题
- 明确输入数据源
- 明确输出格式
- 明确验收标准
- 明确权限和保密要求

输出物：

- 数据工程蓝图
- 输入清单
- 输出清单
- 验收口径

### 采集

采集阶段把数据从来源接入工程流程。

- 确认数据源是否可访问
- 确认采集频率和时间范围
- 确认字段、编码、格式和缺失情况
- 记录采集时间、采集方式和采集人

### 清洗

清洗阶段把数据整理到可处理状态。

- 处理缺失值、异常值和重复记录
- 统一字段名、类型、单位和编码
- 保留清洗规则和变更记录
- 区分自动清洗和人工修正

### 治理

治理阶段把数据变成可复用资产。

- 建立数据字典
- 建立字段口径
- 建立质量规则
- 建立权限和保留周期
- 建立版本和追溯记录

### 计算

计算阶段把处理逻辑放进可复现的流水线。

- 明确计算入口
- 明确依赖环境
- 明确参数和资源档位
- 明确运行日志
- 明确失败重试和回退规则

### 交付

交付阶段不能只交一个结果文件。

- 交付结果数据
- 交付报告说明
- 交付口径解释
- 交付运行证据
- 交付已知风险和限制

### 复盘

复盘阶段把这次工程沉淀成下一次可复用的经验。

- 记录耗时和成本
- 记录异常和修复方式
- 记录可复用模板
- 记录需要产品化的能力
- 记录下一次优化方向

## 执行契约

### 输入契约

输入契约描述数据从哪里来、长什么样、能不能用。

- 数据源
- 访问权限
- 字段说明
- 时间范围
- 数据质量基线

### 处理契约

处理契约描述数据怎么被加工。

- 处理步骤
- 运行环境
- 参数配置
- 依赖工具
- 异常处理

### 输出契约

输出契约描述最后交什么。

- 结果表
- 指标口径
- 报告文件
- 可视化材料
- 审计证据

### 审计契约

审计契约描述怎么证明这次处理可信。

- run id
- job 状态
- 开始和结束时间
- 输入和输出校验结果
- 成本和资源记录
- 人工修正记录

## 托管执行

托管执行把一次数据工程统一成一次 run。

```text
单价 = 执行时长 × 资源档位系数 × 是否可抢占
```

AI、统计计算、报告生成、模板实例化都可以作为一次 run 里的 resource。对外只需要讲一次执行的价格，对内再记录计算、存储、AI 调用和人工处理成本。

## 交付标准

- 有明确的任务边界
- 有可访问的数据源记录
- 有可复现的处理流程
- 有质量检查结果
- 有报告和证据链
- 有成本和耗时记录
- 有后续维护建议

## 快速检查

- 输入是否完整
- 字段口径是否明确
- 清洗规则是否留痕
- 流水线是否可复现
- 结果是否通过验收
- 证据链是否完整
- 复盘记录是否补齐
