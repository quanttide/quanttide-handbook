# 生成式人工智能手册

量潮工作手册研发目录下的生成式人工智能子手册，记录模型、场景、行业、提示词工程、RAG、微调、智能体和具体工具链。生成式 AI 可以提速，但不能替代目标定义、事实校验、风险判断和最终背书。

## 手册结构

源素材把生成式人工智能手册分成前后两部分。

前半部分面向非开发者：

- 模型：围绕基础模型本身，是基础设施。
- 场景：按提示词和任务相似度分类，是 AIGC 视角的领域。
- 行业：按行业使用场景划分，是 AIGC 视角的应用。

后半部分面向开发者：

- 调优方法。
- 智能体建模框架。
- 单智能体和多智能体。
- 被制作出来的智能体应用。

编制重点不是罗列工具，而是不断总结各行业使用经验，理解模型在具体场景中的优缺点，并把使用者经验转化为可复用的代码和工作流。

## 生成任务边界

- 需求澄清、方案草拟、文案生成、结构整理、代码草稿和复盘总结。
- 写作、阅读、对话、编程、短视频、数字人、教育、电商、设计等场景。
- 需要提示词、上下文、检索、工具调用和人工审校协同完成的任务。
- 需要保留提示词、输入材料、模型版本、输出结果和校验记录的工作。

## 模型和工具地图

源素材中出现的模型和工具要按类型记录，不能只写“选择合适模型”。

| 类型 | 工具或模型 |
|------|------------|
| 语言模型 | GPT、Claude、Kimi、通义千问、智谱清言 |
| 图像模型 | Midjourney、Stable Diffusion、DALL-E |
| 音频和 TTS | OpenAI TTS、ElevenLabs、Suno、GPT-SoVITS、Amazon Polly |
| 视频模型 | Sora、Open-Sora、Runway、Pika、Latte |
| 搜索工具 | 秘塔 AI、Morph、Meta AI |
| 向量数据库 | Chroma |
| LLMOps 平台 | RAGFlow、Dify、Amazon Bedrock |
| 数据库查询 | SQLCoder、DB-GPT |
| 数字人 | HeyGen、飞影数字人、剪映、SadTalker |

这些工具的记录要保留具体优缺点。例如：

- Sora 是 OpenAI 视频生成模型，效果强，但短期内其他团队很难弯道超车。
- Runway 是老牌视频生成 AI，效果较好，但可用片段时长和稳定性要评估。
- GPT-SoVITS 只需要较短音频即可做声音克隆，但要检查授权和声音使用边界。
- ElevenLabs 声音效果好，但语言范围、免费额度和接口成本要单独确认。

## 模型使用原则

- AI 负责生成、整理、补全和比较，不负责最终背书。
- 输出必须能追溯输入、上下文、模型版本和关键参数。
- 先定任务目标、风险等级和验收方式，再选模型和提示方式。
- 生成结果必须经过人工校验，不能直接当事实、制度或承诺。
- 敏感信息、客户数据、密钥和未公开材料进入模型前必须先判断权限和脱敏方式。
- 有价值的失败样本、修改痕迹和校验结论要保留下来，方便下一次改进。

## 提示词工程

源素材中的提示词工程关注：

- 引导 AI Think Step By Step。
- 比较命令式语气、请求式语气和激励性提示对生成效果的影响。
- 对提示词进行试验、记录和复盘。

提示词不是越长越好，而是要让模型知道目标、边界、上下文、输出格式和评价标准。

提示词记录至少包括：

- 任务目标。
- 输入材料。
- 输出格式。
- 约束条件。
- 模型和版本。
- 结果评价。
- 修改原因。

### 提示微调

源素材提到 Coze、智谱清言等平台提供提示微调或 Bot 商店能力。

适用场景：

- 同类任务重复出现。
- 需要固定角色、语气、输出格式。
- 需要把少量知识和工作流封装成可复用机器人。

上线前仍要检查事实、版权、敏感信息和对外承诺。

## RAG 和微调

RAG 适合把知识库、文档和检索能力接入生成流程。源素材中出现的相关工具包括 RAGFlow、Dify、Amazon Bedrock 和 Chroma。

RAG 任务要记录：

- 知识库来源。
- 分块策略。
- 向量数据库。
- 检索参数。
- 引用和证据。
- 未命中和误召回样例。

微调适合任务稳定、样本足够、输出标准明确的场景。微调前要确认训练数据质量、权限和评估方法。

## 写作场景

写作流程可以结构化。每个阶段的提示词只做该阶段的事情，同时保留用户主动控制空间。

常见写作场景：

- 学术写作。
- 商务写作。
- 科普写作。
- 创意写作。
- 在线写作。
- 技术写作。

商务写作提示词应包含：

- 原始内容。
- 目标读者。
- 写作类型。
- 输出形式。
- 评价标准，例如正式、清晰、简洁、直白、礼貌、逻辑。

源素材记录过一个现象：加入提示词以后，某些模型输出反而可能变差，例如输出很多要点但不成段落。因此提示词要验证，不要假设越复杂越好。

## 阅读和搜索

阅读场景包括摘要和搜索。

高等教育备课场景中，源素材提到可以使用秘塔 AI 搜索资料。使用搜索工具时要保留来源，不把搜索摘要直接当事实。

## 编程场景

编程场景里，源素材特别提醒：先查资料再生成代码，准确程度会提高。

Flutter 编程场景：

- 知识库：Flutter 官方文档和第三方库文档。
- 检索方式：可以通过 Web Search 获取资料。
- 外部工具：Flutter 官方工具、静态检测工具、测试工具、DevTools。
- 多模态能力：如果模型能读页面，可以用来判断 UI 是否合适。

数据库查询场景：

- SQLCoder：将自然语言问题转换为 SQL 查询。
- DB-GPT：本地化 GPT 大模型与数据和环境交互，适合隐私数据库垂直场景。

编程类 AI 产出必须运行、测试和安全检查，不能只看回答看起来合理。

## 对话和客服

对话场景包括销售、客户服务、助手和情感陪伴。

智能客服源素材观点：

- 传统呼叫中心功能单一，AI 接入后可以和用户进行更自然交互。
- 可以区分完成服务目标的模型和以转化为主的模型。
- 国内 AI 和真人仍有差距。
- OpenAI 服务在部分网络条件下可能存在延迟问题。

客服和销售场景要特别检查：

- 是否误导用户。
- 是否承诺无法兑现的事项。
- 是否泄露客户信息。
- 是否有人工接管路径。

## 心理咨询场景

源素材明确提醒：当前大模型能力还很难达到通用心理咨询需求。

原因包括：

- 需要判断输入是否属于心理咨询范围。
- 需要判断用户心理状态。
- 需要选择心理咨询流派和方法。
- CBT 等体系复杂，不是几个 Prompt 可以概括。
- 心理咨询师需要大量训练。

因此心理相关场景只能做低风险辅助，不能包装成真正心理咨询能力。

## 新媒体短视频

源素材给出一个短视频工作流：

1. GPT 生成文案。
2. GPT 生成分镜。
3. GPT 生成脚本。
4. Midjourney、ElevenLabs、HeyGen 生成物料。
5. 剪映整合剪辑。

这个流程要记录每一步的输入、输出、素材版权和人工审核结论。

## 数字人

数字人源素材区分了几类形态：

- 基于 AI 视频生产的数字分身，通常是 2D 图片动起来，长期使用可能需要持续付费。
- 游戏引擎中的数字人或 NPC，动作和形态更成熟，商业模式不同。
- 对接知识库和 TTS 的数字人，可以满足部分当前应用需求。

风险和限制：

- 外貌和动作可能不完善。
- 与真人差距仍然明显。
- 本地部署需要大量算力资源。
- 2D/3D 数字人、知识库和 TTS 串成完整工作流的平台仍需评估。

## 教育和培训

职业教育场景中，源素材提到可以用 AI 形成完整培训：

- AI 生成提纲。
- 使用脚本和模板生成 PPT。
- 可关注 PPTCopilot。

备课场景中可以用秘塔 AI 搜索资料，但仍要回到原始资料校验。

## 生成前后检查

- 任务属于模型、场景还是行业问题
- 使用了哪个具体模型或工具
- 是否记录提示词、上下文、模型版本和参数
- 是否需要 RAG、微调或智能体
- 输出是否经过事实校验
- 敏感信息是否剔除或脱敏
- 版权和素材授权是否检查
- 是否存在心理咨询、医疗、法律、财务等高风险误用
- 结果是否能回退或人工接管
- 有价值的失败样本是否已沉淀
