# 生成式人工智能手册

量潮工作手册研发目录下的生成式人工智能子手册，讲的是怎么把模型、提示词、上下文、工具、校验和交付连成一条可执行的生成流程。

## 适用范围

- 适用于需求澄清、方案草拟、文案生成、结构整理和复盘总结。
- 适用于需要把 AI 嵌进产品、运营、研发和知识管理流程的场景。
- 适用于需要提示词、检索、工具调用和人工审校协同完成的任务。

## 工作原则

- AI 负责生成和辅助，不负责最终背书。
- 输出必须能追溯输入、上下文和版本。
- 先定目标，再选模型和提示方式。
- 生成结果必须经过人工校验，不能直接当事实。
- 需要保留失败样本、修改痕迹和复盘记录。

## 角色分工

- 负责人负责确认目标、范围、验收口径和风险边界。
- 提示设计负责组织上下文、约束和输出格式。
- 审核负责检查事实、逻辑、版权和敏感信息。
- 平台负责模型接入、权限、日志和计量。
- AI 负责生成初稿、提炼结构、补齐空缺。

## 关键对象

| 对象 | 含义 |
|------|------|
| `prompt` | 任务说明和约束 |
| `context` | 背景材料、输入文档和历史记录 |
| `model` | 负责生成的模型 |
| `tool` | 检索、执行、分析或调用的外部能力 |
| `run` | 一次生成任务 |
| `artifact` | 生成出来的内容 |
| `eval` | 结果校验和评分记录 |

## 工作链路

### 澄清

先把问题讲清楚。

- 明确要解决什么
- 明确不能做什么
- 明确输出格式
- 明确验收方式

### 编排

把上下文和提示词组织好。

- 选择输入材料
- 选定模型和工具
- 设定约束条件
- 设定输出结构

### 生成

让模型开始产出内容。

- 保留输入记录
- 记录模型版本
- 记录参数和温度
- 记录中间结果

### 校验

对生成结果做审查。

- 检查事实是否正确
- 检查逻辑是否完整
- 检查格式是否符合
- 检查是否存在敏感内容

### 交付

把结果交出去，但要带着依据。

- 输出正文或草稿
- 输出引用和依据
- 输出待确认事项
- 输出回退方案

### 复盘

把一次生成变成可复用方法。

- 记录有效提示词
- 记录失败样例
- 记录成本和耗时
- 记录后续优化点

## 主要产出

- 提示词草稿
- 生成结果
- 校验记录
- 参考材料清单
- 复盘总结

## 常见场景

- 需求说明草拟
- 方案结构整理
- 产品文案生成
- 会议纪要归纳
- 知识问答整理
- 代码片段或脚本草稿

## 快速检查

- 目标是否明确
- 输入是否完整
- 输出格式是否明确
- 事实是否已校验
- 敏感信息是否剔除
- 版权风险是否检查
- 结果是否能回退
