# Python手册

量潮工作手册语言、框架和工具目录下的 Python 子手册，讲的是怎么把 Python 用在脚本、服务、数据处理、自动化和交付流程里，并把开发、测试、发布和维护连成一条可执行的线。

## 适用范围

- 适用于 Python 脚本、工具、CLI、服务和数据处理任务。
- 适用于需要把依赖、环境、测试和发布一起管理的项目。
- 适用于需要把 Python 作为通用执行语言的工作场景。
- 适用于需要 AI 辅助编写、审查和整理 Python 代码的情况。

## 工作原则

- 先定环境，再写代码。
- 先定依赖，再定实现。
- 先定测试，再定发布。
- 代码、配置和文档要一起对齐。
- 生成式辅助可以用，但必须人工确认。

## 角色分工

- 负责人负责确认目标、范围和交付口径。
- 开发负责实现、调试和维护 Python 代码。
- 测试负责验证功能、边界和回归。
- 平台负责运行环境、依赖安装和发布流程。
- AI 负责辅助起草、解释错误和整理结构。

## 关键对象

| 对象 | 含义 |
|------|------|
| `project` | Python 项目本体 |
| `environment` | 运行环境 |
| `dependency` | 依赖包和版本 |
| `script` | 一次性执行脚本 |
| `package` | 可复用包 |
| `test` | 测试用例 |
| `artifact` | 构建或发布产物 |
| `release` | 发布记录 |

## 工作链路

### 环境

先把 Python 环境准备好。

- 确认 Python 版本
- 确认虚拟环境工具
- 确认依赖安装方式
- 确认系统路径和权限

### 结构

把项目结构整理清楚。

- 明确入口文件
- 明确包结构
- 明确配置文件
- 明确测试目录

### 开发

开发阶段只做可追踪的改动。

- 保持函数和模块职责清楚
- 避免过度耦合
- 保留必要注释
- 记录关键变更

### 测试

测试阶段确认代码不是只“能跑”。

- 写单元测试
- 写必要的集成测试
- 覆盖边界条件
- 检查回归风险

### 发布

发布阶段把稳定版本交出去。

- 固定版本号
- 锁定依赖
- 生成发布产物
- 保留发布证据

### 维护

维护阶段处理后续变化。

- 修复 bug
- 升级依赖
- 记录兼容性变化
- 保持文档同步

## 常见场景

- 自动化脚本
- 命令行工具
- Web 服务
- 数据采集和处理
- 文档转换和批处理
- AI 辅助工作流

## 交付标准

- 有明确的运行入口
- 有可复现的环境说明
- 有锁定过的依赖版本
- 有测试和回归记录
- 有发布说明和变更记录
- 有必要的回退方式

## 快速检查

- Python 版本是否明确
- 依赖是否锁定
- 入口是否清楚
- 测试是否通过
- 配置是否齐全
- 发布是否可回退
- 文档是否同步
